# astrbot_plugin_kook_music

面向 KOOK 平台的 AstrBot 语音点歌插件。插件会自动加入点歌用户所在的语音频道，通过 FFmpeg 推送音频，并提供 KOOK 卡片按钮控制播放。

## 功能

- 网易云、QQ 音乐、酷狗、酷我、咪咕、百度等平台搜索
- 网易云单曲、歌单和电台节目导入
- B 站关键词、视频、分P、收藏夹和官方短链音频播放
- B 站长视频即时流式播放，避免等待数小时媒体完整下载
- 播放队列、插队、切歌、循环模式和清空队列
- KOOK 卡片按钮控制下一首、循环、清空、停止和快进/快退
- relay/direct 两种语音推流模式
- 严格限定 KOOK 平台；其他平台命令静默忽略

## 下载策略

导入歌单时只获取歌曲元数据并加入播放队列，不会立即批量下载全部歌曲。默认在播放当前歌曲时，后台最多预准备下一首普通歌曲；首曲及未预备的歌曲仍在轮到队首后下载。B 站视频不参与后台预准备。

达到 `bili_stream_threshold_minutes` 的单个 B 站视频/分P以及未知时长视频，会在真正轮到播放时解析临时音频流并直接交给 FFmpeg，不等待完整文件下载。临时签名地址不会在导入时提前获取或写入卡片，循环重播时也会重新解析。

长视频流如果中途异常断开，插件会 fresh 解析一次签名地址，并从已播放位置前约 5 秒续播；不会无限重试。播放准备期间点击“下一首”会取消当前解析/下载并立即推进队列。

从 v1.9.8 起，B 站只选择独立音频轨（优先 M4A），不回退下载视频画面。长视频流解析失败会明确报错，不再静默下载整段数小时音频；`bili_stream_threshold_minutes=0` 仍代表用户主动禁用流式。

relay 远程流默认先缓存 **15 秒音频** 再开始，边播边提前解码缓存最多 **120 秒**；缓存耗尽后补足 **5 秒** 再恢复。这里是音频时长，不是固定等待时间，下载足够快即可尽快开播。每次缓冲最多等待 30 秒，失败走原有有界刷新续播；短于缓冲目标的音频在正常 EOF 后直接播放。缓冲等待不消耗歌曲播放超时，续播位置只累计实际输出的音频。

这是有界内存 PCM 缓存，不保存整段长视频；120 秒约 23 MB/频道，最大可设 300 秒约 58 MB/频道（另有 FFmpeg 管道、解码器等开销）。停止、切歌、退出和卸载会清理缓存。普通已下载歌曲仍立即播放，不强制等待 15 秒。仅 `relay` 支持该缓冲策略，`direct` 不支持。

解码器异常退出时先播完已有的可用缓存，再刷新链接续播，不立即丢弃已缓冲音频。KOOK 卡片的原生倒计时仍是预计结束时间，不会随网络重缓冲暂停；实际播放与恢复位置以已输出音频为准，不受卡片归零影响。

约 10 Mbps 可用下行足以承载常见数百 kbps 音轨，120 秒缓存用于吸收短时网络抖动，而不是预占 120 秒等待。解析/CDN响应、服务器CPU负载等仍影响开播时间；30 秒是缓冲阶段限时，不是含所有解析与连接重试的总开播保证。长期下载速度低于音频码率时，任何有限缓存都无法保证永不卡顿。

`#点歌` 检测到链接时先识别资源：单曲直接解析，歌单提示改用 `#导入歌单`，B站视频转入播放流程；未知/损坏链接不再当作歌名搜索。`id=null`、无有效 ID 或相互冲突的 ID 会提示重新复制链接，分享参数 `uct2` 不作为歌单 ID 猜测。官方短链匿名展开限定平台与总等待时间；`#导入歌单` 误收单曲链接也会提示换用 `#点歌`。

这可以避免大型歌单立即占用大量带宽和磁盘。`prefetch_next` 可关闭后台预准备；单曲循环、随机模式和 B 站内容不提前准备。若在下一首准备完成前切歌，或外部解析源不可用，仍可能存在等待，不保证网络歌曲零间隔。

点歌、播放视频或导入歌单从解析开始到入队期间会暂停该语音会话的空闲退出计时。空闲连接优先复用，不再为新歌曲无条件退出重连；已开始退出的清理会先完成，再加入新请求。实际被移出语音频道时仍终止并丢弃旧请求，不自动重新加入。

新增 **停止** 按钮和 `#停止播放`：停止当前歌曲、清空待播与预准备内容，保留语音连接；之后按正常空闲超时退出。仍仅允许当前点歌者或 KOOK 管理员使用。原“清空”只清待播、“下一首”只跳过当前、“退出语音”断开频道，语义均保留。

从 v1.9.7 起，relay 模式在停止或自然播空后保留健康的编码器，以小流量静音 RTP 维持同一传输和时钟，重新点歌无需原地更换 Producer。空闲自动退出、被踢或插件卸载时仍会关闭中继；`auto_leave_timeout=0` 则按配置持续保留语音连接与静音中继。若中继已损坏，完整重连语音后再播放，不把本地进程存在当作服务端协商成功。

### 播放时间跳转 (v1.9.12)

使用 `#跳转 90`、`#跳转 1:30` 或 `#跳转 1:02:30` 跳到当前音频的指定位置（秒、分:秒、时:分:秒），也可点击播放卡片的「快退 15 秒」「快进 30 秒」。仅当前点歌者或 KOOK 管理员可用；普通歌曲和 B站音频均支持，待播队列与循环模式不变。

跳转命令与两个按钮共享每个服务器的冷却，`seek_cooldown_seconds` 默认 5 秒，范围 1–60 秒。准备、切歌或跳转中的操作会被拒绝，不排队积压；未知时长、非法时间或超出当前音频的目标不会执行。快退不足 15 秒时回到开头。流式内容会重新从目标位置缓冲，因此不是瞬时跳转；倒计时重发时根据实际已播音频校正。原连续「下一首」语义保持不变。

B站封面优先使用投稿封面，仅缺失时回退到分P首帧；短视频本地音频下载使用 1 MiB Range 分块，兼容部分 CDN 对整文件请求返回 HTTP 567 的情况，不下载视频画面。

### 播放卡片与待播队列编辑 (v1.9.6)

发送卡片同时接收 HTTP 与本机器人网关回执，避免“卡片已发出、HTTP 超时没有拿到消息 ID”后无法清理。KOOK 的 `nonce` 仅用于关联回执，**不是幂等键**；不确定是否发出时不会直接重发。参见 [KOOK 消息接口](https://developer.kookapp.cn/doc/http/message)。

卡片 ID、频道及 Token 摘要保存在插件数据目录的 `playing_cards.json`，不保存 Token 或消息正文。跳过/停止会把旧卡加入清理；后台每 30 秒继续尝试失败项，重载后也会恢复。首次接入、发送结果不确定以及周期复查时，有限检查已登记频道最近 150 条消息，只认当前机器人发送、带本插件播放标题/水印/按钮的播放卡。周期复查每频道至少间隔 5 分钟，每轮最多检查一个频道，补偿极晚回执。网络异常或缺少权限时保留记录，不承诺即时删除。

管理员可发送 `#清理音乐卡片`，检查当前文字频道最近最多 500 条消息并回收旧播放卡，保留当前播放卡片。不会清理用户消息、其它机器人、搜索结果或普通“已加入队列”卡片；更早的历史可再次执行清理。

编辑示例：先用 `#歌单` 或 `#歌单 2` 查看最新全局序号，然后使用 `#队列删除 5`、`#队列移动 8 3`、`#队列置顶 8`。移动目标是调整完成后的序号；置顶指下一首，不替换当前歌。第 1 首正在播放/准备，不可删除或移动。普通用户只可操作自己点的待播歌曲，管理员可操作全部；切歌中暂时拒绝编辑，队列变化后请重新查看序号。

### QQ 解析主备源与账号取歌

- `qq_vip_resolver_url` 为主源，`qq_vip_resolver_backups` 为优先级有序的备用列表（最多 3 个，自动去重）。主源留空会关闭整个额外解析链路。
- 官方匿名地址优先；主源失败时按相同 MID 换源，不按歌名替换 DJ、现场或翻唱版本。多源共用 15 秒预算，避免备用数量增加导致切歌等待成倍增长。
- `qq_vip_resolver_cooldown_seconds` 默认 60 秒；同源累计两次临时网络/服务故障后短暂跳过，冷却结束自动恢复尝试，0 可禁用。某一歌曲无匹配或受限不代表整个站故障。
- `522` 是解析链路 HTTP 错误，不应直接归类为会员限制。需结合响应服务器、访问节点和日志确认原因；本机能访问不代表机器人服务器同样可访问。
- 不预置未经验证的公共备用站。端点能返回歌曲信息或 HTTP 200，不代表能获取有效音频。
- 推荐备用是自行部署、由自己控制的兼容服务，使用自己有效的 QQ 音乐登录状态取歌。账号权益、地区和歌曲授权仍然适用；不保证所有歌曲可播。
- 当前额外解析协议支持 Meting (`server=tencent&type=song/url&id=MID`) 与 ygking (`song/url?mid=MID&quality=...`)。不能仅凭路径名相似，就把不兼容的 QQMusicApi 服务填入配置。
- 从 v1.9.0 起支持下方 KOOK 管理员私聊扫码登录，不需要公共站承接 Cookie。也可继续使用管理员自建的兼容取歌服务。不要在群聊、日志、仓库或公共解析网站提交密码、Cookie、JWT。

### KOOK 私聊音乐账号登录 (v1.9.0)

在插件配置填写 `music_auth_admin_ids`（数字 KOOK 用户 ID，不是昵称或 `#识别号`）。只有名单中的账号所有者可以操作音乐登录，普通 KOOK 服务器管理员不会自动获得这个权限。`music_auth_enabled` 默认开启，但名单为空时账号模块完全不启动。

存在多个 KOOK 机器人时，必须在 `music_auth_kook_bot_id` 指定 AstrBot 的适配器实例 ID；单实例可以留空自动选择。登录开始、取消和二维码结果绑定同一个机器人和同一个发起者，其他管理员也不能抢占正在进行的登录。

| 管理员私聊命令 | 功能 |
| --- | --- |
| `#音乐登录 qq` | 用手机 QQ 扫码登录 QQ 音乐 |
| `#音乐登录 微信` | 用微信扫码登录 QQ 音乐；与 QQ 登录共用一个 QQ 音乐账号槽位 |
| `#音乐登录 网易云` | 用网易云音乐 App 扫码登录 |
| `#音乐登录 网易云网页` | 生成官网网页协议的二维码，仍用网易云音乐 App 扫描 |
| `#音乐登录 B站` | 用哔哩哔哩 App 扫码并确认，自动保存和启用登录态 |
| `#音乐账号状态` | 查看 QQ／网易云／B站登录状态，不显示 Cookie、Token 或完整账号信息 |
| `#音乐Cookie 网易云` | 开始私聊导入，下一条发送完整 JSON / Header String / Netscape Cookie |
| `#音乐Cookie B站` | 开始 B站 Cookie 私聊导入，支持相同三种导出格式 |
| `#音乐验证 网易云` | 兼容旧命令，等同开始私聊 Cookie 导入，不再发网页链接 |
| `#取消音乐登录 qq` / `#取消音乐登录 网易云` | 取消本人当前扫码流程 |
| `#退出音乐账号 qq` / `#退出音乐账号 网易云` | 删除服务器保存的对应登录凭据 |
| `#取消音乐登录 B站` / `#退出音乐账号 B站` | 取消 B站扫码／删除本插件保存的 B站账号 |

一般命令的唤醒前缀以 AstrBot 配置为准。Cookie 导入请使用上述专用私聊命令，等待机器人确认后再发送，不要把密码或 Cookie 发到频道、群聊或其它命令里。

登录成功前保留原账号，新凭据通过官方有效性检查后才原子替换。二维码只在明确的私聊登录请求后生成；默认最长等待 180 秒，可配置 30-300 秒，并受平台二维码有效期限制。授权成功、取消、过期和卸载时停止轮询并尝试撤回二维码消息。

QQ 扫码确认后仍需完成授权交换，请等待机器人最终提示。v1.9.1 起，临时故障会在原截止时间内连续最多重试三次，不重做已完成的 QQ 授权阶段；明确协议错误会停止并显示 `QQ_CALLBACK`、`QQ_CHECK_SIG`、`QQ_OAUTH` 或 `QQ_EXCHANGE` 等安全阶段标识。反馈错误时只需提供该标识，不要提供二维码、Cookie 或回调链接。

v1.9.2 已通过实际账号扫码确认，修复 `QQ_CHECK_SIG` 中不同域同名 Cookie 被覆盖的问题。签名响应的 Cookie 按域、路径和有效期处理，不把过期删除项当作新登录凭据。

网易云若返回 **8821 / NETEASE_VERIFY**，表示官方要求人工行为验证、尚未签发登录凭据。插件会停止重试并保留原账号，请按网易云官方页面的提示完成验证，不要把重复扫码当作解决办法。`网易云网页` 是按官网 type=1 协议的兼容模式，不保证消除验证码；此模式也不会绕过 8821 或伪造登录成功。网易云 Cookie 同样严格处理域、路径和过期规则，不读取公共代理返回的 Cookie 正文。

#### B站扫码与三格式 Cookie (v1.9.10)

推荐向配置中的 KOOK 机器人私聊 `#音乐登录 B站`，使用哔哩哔哩 App 扫码并在手机确认。仅在明确请求后生成二维码，默认最多等待 180 秒；成功后先经官方登录接口校验，再加密保存到 `music_accounts/accounts.enc`，立即用于视频、音频及收藏夹解析，无需复制 Cookie 或重载插件。支持当前官方的一次性 ticket 换取 Cookie 流程；票据兑换失败需重新发起二维码，失败阶段为 `BILIBILI_TICKET`，不会重用已消费的票据。

也可私聊 `#音乐Cookie B站`，收到提示后发送 Cookie-Editor 的 **JSON 数组、Header String、Netscape** 之一。代码块与多行内容均可；只保留 SESSDATA、bili_jct、DedeUserID、DedeUserID__ckMd5、buvid3、buvid4，忽略统计字段。过期、跨域、账号字段冲突或无效输入不会覆盖旧账号。过期接收窗口还会短暂保护下一条迟到的私信；务必在新窗口确认后提交，不要向频道发送 Cookie。

插件配置 `bili_cookie` 已改为多行文本，同样接受三种导出及原来的裸 SESSDATA。旧 `bili_cookies.txt` 可继续只读加载。扫码／私聊保存的账号优先于旧配置和旧文件，防止重载把新 Cookie 覆盖回去；使用 `#音乐Cookie B站` 可替换已有账号。首次启用时，已有配置若通过官方校验也会导入加密存储。

B站 Cookie 仅在解析器内存 CookieJar 中使用，限定到 Bilibili 域；不会写出新的明文 cookies 文件，也不把登录 Cookie 转发给音频 CDN。切换或注销账号会使旧请求和解析线程结果失效，避免旧数据回填。`#退出音乐账号 B站` 同时停用旧配置／文件的自动恢复，需重新扫码或私聊导入才启用；不会修改 QQ 和网易云账号。

B站登录失效时会提示重新扫码；当前不实现需额外官方验证的 Cookie 刷新流程，不保证会员、地区或失效视频均可播放。协议参考 [Bilibili QR 登录资料](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/login/login_action/QR.md)。

#### 网易云三格式 Cookie 私聊导入 (v1.9.5)

已移除手动接入网站及 `music_auth_web_base_url` / `music_auth_web_ttl` 配置，不再需要先登录 AstrBot 后台。已有 HTTPS 后台和反向代理无需删除。

1. 在 **网易云官网** 正常登录并完成人工安全验证，导出自己账号的 Cookie。
2. 白名单管理员向指定 KOOK 机器人私聊 `#音乐Cookie 网易云`，收到等待提示后，在默认 180 秒内发送一条完整 Cookie 文本；等待时长可配置 `music_auth_cookie_timeout`（30-600 秒）。
3. 支持 Cookie-Editor 的 **JSON 数组、Header String、Netscape** 三种导出，也支持仅 `MUSIC_U=...; __csrf=...`。多行内容可包在代码块内，防止聊天格式化破坏下划线和制表符；不要手改凭据值，不支持分多条拼接或下载附件。
4. 服务器仅向网易云官方验证，确认有效后原子加密替换网易云账号。失败保留旧账号，不影响 QQ。完成后返回固定结果/失败阶段，并尽力撤回收到的 Cookie 消息。

只提取 `MUSIC_U`、`__csrf`、`MUSIC_A`、`MUSIC_R_T` 认证字段；忽略统计 Cookie 的逗号等内容和空可选字段。JSON/Netscape 会校验域、路径、到期时间与同名冲突，不把第三方域的 Cookie 当作网易云凭据。输入上限 64 KiB，最终认证请求头上限 8 KiB，仍受 KOOK 单条消息长度限制；太长时可只发送 `MUSIC_U` 和 `__csrf`。

从 v1.9.11 起，Header String 中不同作用域合并出的多个不同 `__csrf` 会被安全省略，唯一的 `MUSIC_U` 仍可用于官方校验；JSON/Netscape 则继续按作用域选择 CSRF。KOOK 格式化后的文本若漏掉 HttpOnly 认证行，会回退读取消息原文，不修改 Cookie 值。整份 JSON 太长时建议改用 Header String；每次发送一种导出即可，收到的是文件附件时机器人会提示重新粘贴文字。

本流程导入的是 **已经从官网取得的登录态**，不绕过 8821，也不拼造官方验证码地址。新导入、取消、登录/注销、权限或机器人绑定变化及插件卸载会使旧等待失效；不接受频道、非白名单或其它机器人实例提交。

插件在 KOOK 原适配器回调前拦截支持的 Cookie 消息，不把它们交给普通 Core 消息日志、LLM 和后续消息插件；解析、官方校验、保存失败只记录固定阶段/数字业务码，不记录原文。此保护仅在本插件监听已安装时生效，不能阻止 KOOK 平台或更早安装的第三方网关监听器看到私信，也不保证撤回清除所有副本。务必先发送导入命令并收到提示后再提交。

插件启动及默认每 1800 秒检查一次账号状态。QQ 音乐依据完整音乐凭据的创建时间及有效期提前续期，默认提前 3600 秒，最多提前有效期的四分之一；后台会按到期时间提前唤醒，不必等下一次常规检查。缺少可靠有效期时，每 12 小时低频维护；没有刷新令牌的凭据只能使用至平台使其失效。`music_auth_refresh_lead_seconds=0` 关闭按有效期提前续期，未知有效期的低频维护仍保留。

刷新或校验遭遇网络、超时、限流或未知业务错误时，保留加密凭据，按 60 / 120 / 240 秒递增重试，最长间隔 3600 秒；重试时间跨重启保留。仍有效的账号继续取歌。新凭据取得后先原子加密保存为待验证候选，验证暂时失败不会丢弃轮换后的刷新令牌；重启先验证候选，候选的音乐 Key 已过期时使用其新刷新令牌续期，不回用旧令牌。停止或重载时，已在进行的续期会在有界超时内完成候选保存。

只有当前登录已失效且平台明确拒绝续期、或缺少续期材料时，才向白名单私聊提醒重新扫码；默认同类提醒至少间隔 21600 秒（6 小时），去重跨重启保留。提前续期被拒绝但当前 Key 仍有效时继续取歌，直到确实过期。旧版因单次网络故障留下的失效标记会重新检查并尝试恢复，无需先删除账号文件。平台撤销授权或刷新令牌失效后仍需要重新扫码，无法保证永久免登录。

账号取歌仅访问 QQ／网易云官方 HTTPS API，保留原歌曲 MID／ID，不按同名搜索替换歌曲，不接受网易云试听片段。已有可用音频不强制重取；无音频时 QQ 官方匿名结果优先，然后尝试自有账号，再使用配置的公共主备源。网易云有账号时可先取官方完整音频；没有登录或账号线路不可用时保留原解析链路。账号仍需具备对应歌曲权益；扫码成功不保证付费专辑或地区限制歌曲都可播放。

`退出音乐账号` 是删除本插件本地凭据，不是撤销手机端/平台所有会话，也不会回收已发出的临时音频链接或中断当前已下载的歌曲；需要停止播放请使用 `退出语音`。

#### 凭据与部署边界

- 安装更新后的 `requirements.txt`。QQ SDK 固定到已核查的 Git 提交，不能简单替换为同名 `0.7.3` 标签；安装环境需要 Git 和 Python 3.12+。加密与二维码依赖为 `cryptography`、`qrcode[pil]`。
- 凭据及提醒记录保存在 `data/plugin_data/astrbot_plugin_kook_music/music_accounts/accounts.enc`，密钥是同目录 `accounts.key`，采用 Fernet 和原子写入。文件损坏、密钥缺失或运行中被外部修改时，账号模块停止读写，不覆盖原始数据。
- POSIX 下目录权限 0700、文件 0600；Windows 的 `chmod` 不等价于 NTFS ACL，请用专用运行账号并限制目录权限。密钥和密文放在同一主机，**不能防止同一 OS 账号或主机管理员读取**。
- 上述目录、备份、密钥、密文、二维码和日志不可上传 GitHub 或打入插件包。备份时需要同时保护密钥与密文；不要随意删除其中一个文件来“修复”登录。
- 二维码不写本地文件，但为发送图片需上传 KOOK 媒体服务。私聊撤回只删除消息，不承诺清除 KOOK CDN 中的媒体资产；请勿转发二维码。
- QQ 音乐实现基于社区 [QQMusicApi 固定提交](https://github.com/L-1124/QQMusicApi/tree/ba95861ee9391f5b5f60f89caa8d4de4af160c8b)，依赖遵循其 GPL-3.0-or-later 许可；不是 QQ 音乐官方机器人 SDK。
- 网易云采用独立会话直连官方 WEAPI，协议核对自 [api-enhanced 固定提交](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/tree/a8c781fd64faab17fedfd46e0615a2609307f163)。没有向公共 API 站发送用户 Cookie，也不使用进程全局 CookieJar。

QQ 账号已完成一次实际扫码授权、有效性检查和两首指定歌曲的音频头验证；微信及网易云真实账号授权、登录自然过期后的刷新、完整语音播放仍需后续实机验收。

### B 站批量添加

- 未指定 `?p=N` 的多P视频会按 P1、P2、P3 的原始顺序整批加入队列；显式指定 `?p=N` 时只添加该分P。
- 支持空间收藏夹、`medialist`、`list/ml...` 以及 `b23.tv` 官方短链。收藏夹内的多P视频默认只添加 P1，避免递归展开导致队列意外膨胀。
- 收藏夹或多P数量超过实时队列剩余容量时，会要求输入 1-based 闭区间，例如 `201-400`；只读取最终选中区间覆盖的收藏夹分页。
- 批量添加只写入元数据；每个分P轮到播放时才按自身时长选择下载或流式播放，失效或已删除的视频会跳过并显示数量。

示例：

```text
播放 BV1dujdzrEA4
播放 https://www.bilibili.com/video/BV1dujdzrEA4?p=2
播放 https://space.bilibili.com/84912/favlist?fid=213003412
```

## 配置

- `default_platform`：默认搜索平台
- `streaming_mode`：`relay`（推荐）或 `direct`
- `prefetch_next`：默认开启，播放当前歌曲时最多预准备下一首普通歌曲
- `seek_cooldown_seconds`：时间跳转/快进/快退共用冷却，默认 5 秒，范围 1–60 秒
- `bili_stream_threshold_minutes`：B 站单个视频/分P的流式播放阈值，默认 30 分钟；`0` 为禁用
- `stream_startup_buffer_seconds`：relay 远程流开播缓存音频秒数，默认 15，范围 0–30
- `stream_max_buffer_seconds`：relay 远程流最大前向缓存，默认 120，范围 5–300 秒
- `stream_rebuffer_seconds`：relay 远程流断流后恢复目标，默认 5，范围 0–30 秒；前后两个目标不超过最大缓存
- `max_queue_size`：单服务器最大队列长度，配置上限 2000
- `playlist_range_timeout`：大型歌单等待用户输入歌曲区间的超时时间
- `max_sessions`：最大并发语音会话数
- `auto_leave_timeout`：队列空闲后的自动退出时间
- `volume`：FFmpeg 输出音量
- `search_limit`：搜索结果数量
- `custom_ffmpeg_path`：自定义 FFmpeg 可执行文件
- `kook_token`：无法从 KOOK 适配器读取 Token 时手动填写
- `bili_cookie`：可选的 B 站 SESSDATA，用于需要登录的视频和私密收藏夹

请勿将 Token、Cookie 或 AstrBot 运行时数据提交到仓库。
